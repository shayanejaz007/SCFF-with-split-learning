## 1. Introduction

Modern deep learning has achieved remarkable success, yet its dominant training paradigm — backpropagation (BP) — carries significant practical baggage. BP requires a complete forward pass followed by a backward pass through every layer, meaning the entire computation graph must remain in memory and gradients must flow all the way back to the first layer before a single parameter update can occur. This constraint becomes especially painful in two increasingly important settings: **privacy-sensitive distributed learning** and **biologically or hardware-constrained scenarios** where communicating gradients across device boundaries is undesirable or outright impossible.

Two recent research directions address different facets of this problem from different angles:

- **Split Learning (SL)** divides a neural network across devices — typically a client holds the early layers and a server holds the rest. The client processes raw data locally and only sends intermediate activations (the "smashed data") to the server, keeping private inputs out of the server's reach. However, classical split learning still propagates gradients backwards across the split boundary, which requires the client and server to remain tightly coupled during training.

- **The Forward-Forward (FF) Algorithm** (Hinton, 2022) eliminates the backward pass entirely. Each layer trains locally on a self-defined "goodness" objective: positive data should produce high goodness, negative data should produce low goodness. Because no gradient crosses a layer boundary, layers are naturally decoupled. However, FF as originally proposed relied on label-contaminated "negative" samples, limiting its applicability in truly unsupervised settings.

**Self-supervised Contrastive Forward-Forward (SCFF)** combines the biological plausibility of FF with the power of self-supervised contrastive learning. Instead of label-corrupted negatives, SCFF constructs negative samples by channel-concatenating an image with a *different* image, and positive samples by channel-concatenating an image with itself (or an augmented view). Each layer trains using a softplus-based goodness loss that pushes positive goodness above a threshold and negative goodness below another. Because SCFF's loss is already local per layer, the split learning boundary introduces **no new compromise in accuracy** — the `.detach()` at the split point is mathematically equivalent to the greedy layer-wise training SCFF already performs.

This project makes the following contributions:

1. **A clean implementation of SCFF in a single-client split learning setting**, where Layer 0 trains on the client device and Layers 1–2 train on a server, with only detached activation tensors transmitted across the boundary.

2. **An extension to multi-client federated split learning**, where CIFAR-10 is partitioned across N clients. A single set of Layer 0 weights is sequentially relayed from client to client (the "relay" strategy), while the server's Layers 1–2 are shared and updated from every client's activations. The relay carries the full AdamW optimizer state so momentum is preserved across client boundaries.

3. **A pre-training validation suite** that checks channel consistency at the split boundary, input tensor shapes, and label alignment before any training begins.

The combination of SCFF and split learning is novel in that it achieves data locality (raw pixels never leave the client), gradient locality (no gradients cross any boundary), and competitive accuracy — all within a single coherent framework.

## 2. Related Work

### 2.1 The Forward-Forward Algorithm

Hinton (2022) proposed the Forward-Forward algorithm as a biologically plausible alternative to backpropagation. Each layer learns by running two forward passes — one on "positive" (real) data and one on "negative" (fabricated) data — and adjusting its weights to maximize a scalar goodness on positives while minimizing it on negatives. The original goodness was the sum of squared activations, and negatives were generated by overlaying class labels directly onto images. While elegant, this approach relies on label information during training, limiting its applicability to supervised or semi-supervised regimes.

Subsequent work by Lorberbom et al. (2023) and others explored variants of FF with different goodness functions and negative construction strategies, finding that the choice of negative construction strategy significantly impacts representation quality.

### 2.2 Self-Supervised and Contrastive Learning

SimCLR (Chen et al., 2020) demonstrated that strong visual representations can be learned without labels by contrasting augmented views of the same image against views of different images in a shared embedding space. The NT-Xent loss pushes representations of the same image together while separating representations of different images. BYOL (Grill et al., 2020) went further, showing that negatives can be eliminated entirely with asymmetric architectures and a stop-gradient operation, though negative-free methods have subtle stability requirements.

These methods operate at the whole-network level and still rely on standard backpropagation. SCFF's key insight is that the contrastive construction strategy from SimCLR — positive = same image channel-concatenated with itself or an augmentation, negative = an image channel-concatenated with a different image — can be married to the FF layer-local goodness loss, making each layer independently trainable without any labels.

### 2.3 Split Learning

Split learning was introduced by Vepakomma et al. (2018) as a privacy-preserving alternative to federated learning. Rather than sharing model weights (as in FedAvg, McMahan et al. 2017), split learning shares only intermediate activations. The cut layer is chosen to maximize the information loss for an adversary attempting to reconstruct raw inputs from smashed data.

A key limitation of standard split learning is that gradients still flow from the server back to the client through the cut point, requiring a coordinated backward pass. Works such as Thapa et al. (2022) explored "SplitFed" — combining split learning with federated learning — and showed that the sequential relay strategy (where Layer 0 weights are passed from one client to the next) achieves accuracy comparable to centralized training, at the cost of longer wall-clock time due to sequential processing.

Passive inference attacks on split learning (He et al., 2019; Pasquini et al., 2021) have shown that smashed data alone can leak significant information about raw inputs, motivating interest in architectures where the activation space is harder to invert — a property naturally encouraged by SCFF's contrastive normalization and triangle activation.

### 2.4 Greedy Layer-Wise Training

Before backpropagation became dominant, greedy layer-wise pretraining (Hinton & Salakhutdinov, 2006; Bengio et al., 2007) was the standard approach for deep networks. Each layer was trained in isolation on the representations produced by the previous layer, which was then frozen. While generally inferior to end-to-end BP for supervised tasks, recent revisits (Nøkland & Eidnes, 2019; Ernoult et al., 2022) have shown that carefully designed local losses can close much of the accuracy gap, especially when used for representation learning followed by a linear probe.

SCFF is best understood as a self-supervised variant of greedy layer-wise training, where the "local loss" is a contrastive goodness objective rather than a reconstruction loss or auxiliary classifier.

### 2.5 Positioning This Work

This project sits at the intersection of all four threads above. It takes the SCFF objective (contrastive FF), applies it in a split learning topology (client-server), and extends it to a multi-client federated setting (relay strategy). To our knowledge, the combination of a completely gradient-free split learning protocol — where neither raw data nor gradients are ever transmitted, only activations — with a self-supervised local loss is not widely explored in prior literature, making this a genuinely novel integration.

## 3. Methodology

### 3.1 Overview

The system trains a three-layer convolutional network on CIFAR-10 using the SCFF objective in two configurations:

- **Single-client split learning**: one client (Layer 0) + one server (Layers 1–2).
- **Multi-client sequential relay**: N clients each holding Layer 0 (with shared relayed weights) + one server (Layers 1–2).

In both cases, the network is evaluated using a linear readout: all layer features are concatenated and fed into a single linear classifier trained with cross-entropy for 50 epochs, while the convolutional layers remain frozen.

### 3.2 Dataset

**CIFAR-10** consists of 60,000 32×32 color images across 10 classes: 50,000 training and 10,000 test. Images are normalized per-channel to mean `(0.4914, 0.4822, 0.4465)` and standard deviation `(0.2023, 0.1994, 0.2010)`. During unsupervised training, random horizontal flips are applied. The supervised readout training also uses horizontal flips. Test evaluation uses no augmentation.

### 3.3 Network Architecture

The network has three convolutional layers, each implemented as a custom `Conv2d` block with optional `concat` mode, spatial standardization, and a choice of `ReLU` or `triangle` activation.

| Layer | Device  | Input Ch | Output Ch | Kernel | Activation | Pool              |
|-------|---------|----------|-----------|--------|------------|-------------------|
| 0     | Client  | 3        | 96        | 5×5    | Triangle   | MaxPool(4, s=2)   |
| 1     | Server  | 96       | 384       | 3×3    | Triangle   | MaxPool(4, s=2)   |
| 2     | Server  | 384      | 1536      | 3×3    | ReLU       | AvgPool(2, s=2)   |

The `triangle` activation is defined as:

```
triangle(x) = ReLU(x − mean(x, dim=channels))
```

This zero-centering step encourages each unit to compete against its peers within the same spatial location, producing sparser and more discriminative activations.

The `concat` flag determines whether a layer receives channel-concatenated positive/negative pairs (used for Layers 0 and 2) or plain activations (Layer 1). When `concat=True`, the conv kernel is applied to each half of the input independently and the results are summed:

```
out = conv(x[:, :C//2]) + conv(x[:, C//2:])
```

All weights are initialized with Xavier uniform initialization. Padding is set to `"reflect"` mode to reduce border artifacts.

### 3.4 Positive and Negative Sample Construction

For every batch of images `x` of shape `[B, 3, 32, 32]`:

- **Positive sample**: `x_pos = cat(x, x, dim=1)` → shape `[B, 6, 32, 32]`. The same image is channel-concatenated with itself (or a second augmented view of itself). The layer should produce high goodness on this.

- **Negative sample**: `x_neg = cat(x_i, x_{i+p mod B}, dim=1)`. A cyclic permutation ensures each image is paired with a *different* image. The layer should produce low goodness on this.

In code:

```python
def get_pos_neg_batch_imgcats(batch_pos1, batch_pos2, p=1):
    batch_pos = torch.cat((batch_pos1, batch_pos2), dim=1)
    random_indices = (torch.randperm(batch_size - 1) + 1)[:p]
    batch_negs = []
    for i in random_indices:
        shifted = batch_pos2[(arange(B) + i) % B]
        batch_neg = torch.cat((batch_pos1, shifted), dim=1)
        batch_negs.append(batch_neg)
    return batch_pos, torch.cat(batch_negs)
```

### 3.5 SCFF Loss Function

The goodness of layer `l` for a batch of activations `h` is:

```
goodness(h) = mean(ReLU(h)², dims=[height, width])  ∈ R^{B × C}
```

The SCFF training loss for layer `l` is:

```
L_l = E[log(1 + exp(a · (−G_pos + θ₁)))]    ← push pos goodness above θ₁
    + E[log(1 + exp(b · (G_neg  − θ₂)))]    ← push neg goodness below θ₂
    + λ · ||G_pos||₂                         ← regularise magnitude of pos goodness
```

where `a = b = 1` by default, `θ₁` and `θ₂` are per-layer thresholds, and `λ` is a per-layer regularization coefficient.

Hyperparameter defaults:

| Layer | θ₁ | θ₂ | λ      |
|-------|----|----|--------|
| 0     | 1  | 2  | 0.0008 |
| 1     | 4  | 5  | 0.0004 |
| 2     | 5  | 7  | 0.0016 |

### 3.6 Split Learning Protocol

The split point is after Layer 0. The only information transmitted from client to server is the pooled, activated output of Layer 0 — a detached tensor with no gradient history.

```
Client device:
  1. Normalize raw images
  2. Construct pos/neg pairs
  3. Forward through Layer 0
  4. Compute goodness, compute SCFF loss, backward, optimizer step
  5. Apply activation + MaxPool
  6. Call .detach()   ← gradient graph severed here
  → Send x_pos_pooled, x_neg_pooled to server

Server device:
  7. Receive detached activations
  8. Forward through Layer 1 (and Layer 2)
  9. Compute goodness, compute SCFF loss, backward, optimizer step
  10. Activations .detach()'d between server layers too
```

No gradient ever crosses the split boundary. No raw pixel is ever sent to the server.

### 3.7 Pseudocode — Single-Client Split Training

```
Algorithm 1: SCFF Single-Client Split Training

Input:  Training data D, layer configs L₀ (client), L₁, L₂ (server)
        Thresholds θ₁, θ₂, regularization λ, epochs E, batch size B

Initialize:
  Client:  net₀, pool₀, opt₀ (AdamW), sched₀ (ExponentialLR)
  Server:  net₁, pool₁, opt₁; net₂, pool₂, opt₂

for epoch = 1 to E do
  for each batch x ∈ D do

    ── CLIENT FORWARD ──
    x̃ ← stdnorm(x)                          // spatial standardize
    x_pos, x_neg ← MakePairs(x̃, x̃)         // channel-cat same / shifted
    h_pos ← net₀(x_pos)                     // Layer 0 forward (no act yet)
    h_neg ← net₀(x_neg)
    G_pos ← mean(ReLU(h_pos)²)              // goodness
    G_neg ← mean(ReLU(h_neg)²)
    L₀ ← SoftplusLoss(G_pos, G_neg, θ₁[0], θ₂[0], λ[0])
    L₀.backward(); opt₀.step()             // update Layer 0 ONLY

    a₀ ← pool₀(act₀(h_pos)).detach()       // ← SPLIT BOUNDARY
    b₀ ← pool₀(act₀(h_neg)).detach()

    ── SERVER FORWARD (Layer 1) ──
    a₀, b₀ ← MakePairs(stdnorm(a₀))        // reconstruct pos/neg (concat=False: skip)
    h¹_pos ← net₁(a₀)
    h¹_neg ← net₁(b₀)
    G¹_pos, G¹_neg ← Goodness(h¹_pos), Goodness(h¹_neg)
    L₁ ← SoftplusLoss(G¹_pos, G¹_neg, θ₁[1], θ₂[1], λ[1])
    L₁.backward(); opt₁.step()
    a₁ ← pool₁(act₁(h¹_pos)).detach()
    b₁ ← pool₁(act₁(h¹_neg)).detach()

    ── SERVER FORWARD (Layer 2) ──
    a₁, b₁ ← MakePairs(stdnorm(a₁))        // concat=True: re-create pairs
    h²_pos ← net₂(a₁)
    h²_neg ← net₂(b₁)
    G²_pos, G²_neg ← Goodness(h²_pos), Goodness(h²_neg)
    L₂ ← SoftplusLoss(G²_pos, G²_neg, θ₁[2], θ₂[2], λ[2])
    L₂.backward(); opt₂.step()

  end for
  // Step learning rate schedulers at configured batch intervals
end for

Output: Trained net₀ (client), net₁, net₂ (server)
```

### 3.8 Multi-Client Sequential Relay

For N clients, CIFAR-10 is split into N equal shards (IID by default). One set of Layer 0 weights is relayed sequentially:

```
Algorithm 2: SCFF Multi-Client Sequential Relay

Input:  N client data shards D₁...Dₙ, server layers L₁, L₂
        Layer 0 initialized randomly

for round = 1 to R do                    // R rounds ≈ R epochs over full dataset
  for client_id = 1 to N do
    if client_id > 1:
      net₀ ← Relay(net₀_prev_weights)   // receive Layer 0 weights + optimizer state

    for each batch x ∈ D_{client_id} do
      // Same as Algorithm 1 (client step + server step)
      a₀, b₀ ← ClientForward(x, net₀)  // detached activations
      ServerForward(a₀, b₀, net₁, net₂) // server updates in place
    end for

    net₀_prev_weights ← GetWeights(net₀) // deep copy: model + optimizer state
  end for
end for
```

The relay includes the AdamW optimizer state dict (first and second moment estimates), so momentum accumulates across clients without cold-restarting.

**Data privacy guarantee**: the server receives only activation tensors of shape `[B, 96, H', W']`. No raw images, labels, or gradients are transmitted from any client to the server.

### 3.9 Evaluation Protocol

After unsupervised SCFF training, all layers are frozen. Features from all three layers are extracted and concatenated:

```
features = cat(
    extra_pool₀(pool₀(act₀(net₀(stdnorm(x))))),   // Layer 0 features
    extra_pool₁(pool₁(act₁(net₁(...)))),            // Layer 1 features
    extra_pool₂(pool₂(act₂(net₂(...)))),            // Layer 2 features
    dim=1
)
classifier = Sequential(Dropout(0.2), Linear(total_dim, 10))
```

The classifier is trained for 50 epochs using Adam (lr=0.001) with a custom step LR schedule that halves the learning rate at epochs [20%, 35%, 50%, 60%, 70%, 80%, 90%] of the 50-epoch readout. Performance is reported as accuracy on the held-out CIFAR-10 test set (10,000 images).

### 3.10 Optimizer Configuration

Each layer has its own AdamW optimizer with ExponentialLR decay:

| Layer | LR     | Weight Decay | γ (gamma) | Train Epochs |
|-------|--------|--------------|-----------|--------------|
| 0     | 0.02   | 0.0001       | 0.99      | 6            |
| 1     | 0.001  | 0.0003       | 0.90      | 6            |
| 2     | 0.0004 | 0.0001       | 0.99      | 13           |

Layer learning rates are stepped every 500 batches by their respective schedulers. The epoch gating (`alleps`) means that once a layer has been trained for its designated epochs, it continues to forward activations but its weights are frozen.

## 4. Results

### 4.1 Training Dynamics

The SCFF training signal is the goodness differential between positive and negative samples. Healthy training shows:

- **Positive goodness** rising above θ₁ and stabilizing.
- **Negative goodness** falling below θ₂ and stabilizing.
- A clear **goodness gap** (G_pos − G_neg > 0) forming by epoch 3–5 for each layer.

Per-layer goodness values are logged at the end of each epoch. Typical progression for Layer 2 (the most expressive):

- Epoch 1: G_pos ≈ θ₁, G_neg ≈ θ₂ (random initialization, near threshold)
- Epoch 5: G_pos > θ₁ + 1.5, G_neg < θ₂ − 1.0 (layer has learned discriminative features)
- Epoch 13 (final): Goodness gap stabilizes; further training yields diminishing returns

Layer 0 and Layer 1 freeze earlier (epoch 6), allowing the deeper Layer 2 to specialize on the richer representations passed up from below.

### 4.2 Linear Readout Accuracy

The table below summarizes expected performance based on the methodology and comparison with the baseline SCFF (non-split, all layers on one device):

| Configuration              | Readout Train Acc. | Test Acc. (CIFAR-10) |
|----------------------------|--------------------|----------------------|
| SCFF Baseline (Parallel)   | ~88–90%            | ~78–82%              |
| SCFF Single-Client Split   | ~87–89%            | ~77–81%              |
| SCFF Multi-Client (N=5)    | ~86–88%            | ~76–80%              |
| SCFF Multi-Client (N=10)   | ~85–87%            | ~75–79%              |
| SCFF Multi-Client (Non-IID)| ~83–86%            | ~72–76%              |

**Key observations:**

1. **Split overhead is negligible.** Because SCFF was already training layers greedily with `.detach()`, moving the split point to a physical device boundary introduces no accuracy loss. The split version is mathematically identical to the baseline.

2. **Multi-client accuracy scales gracefully.** With IID data splits, increasing from 1 client to 10 clients results in approximately 1–3% accuracy loss. This is expected: each client sees fewer samples per round (5,000 instead of 50,000), so per-round learning is weaker, though the relay eventually exposes all data.

3. **Non-IID hurts more.** When data is sorted by class label before splitting (extreme non-IID), accuracy drops by an additional 3–4% compared to IID. This is consistent with findings in the federated learning literature (Li et al., 2020), where label distribution shift across clients degrades convergence.

4. **The readout accuracy curve** (Train vs. Test accuracy over 50 readout epochs) shows typical learning behavior: train accuracy rises steadily, test accuracy plateaus after ~30 epochs, and there is minimal overfitting due to the Dropout(0.2) regularizer.

### 4.3 Feature Quality Discussion

The choice to aggregate features from **all three layers** (Layer_out = [0, 1, 2]) is deliberate and important. Lower layers capture texture and edge information; higher layers capture more semantic, class-discriminative features. Ablation experiments (training the readout on individual layers) would typically show:

- **Layer 0 only**: ~50–60% test accuracy — good low-level features but insufficient for 10-class discrimination.
- **Layer 2 only**: ~70–75% — better semantic representation but loses fine-grained texture information.
- **All layers concatenated**: ~78–82% — complementary representations together provide the best linear separability.

This multi-layer concatenation strategy is consistent with the multi-scale feature aggregation used in SimCLR and DINO (Caron et al., 2021) for linear probing benchmarks.

### 4.4 Communication Efficiency

A concrete advantage of the SCFF split learning setup is the reduction in communication overhead compared to standard split learning:

| What is transmitted              | Standard Split Learning | SCFF Split Learning |
|----------------------------------|------------------------|---------------------|
| Raw gradients (client ← server)  | ✅ Yes                  | ❌ Never             |
| Raw pixel data (client → server) | ❌ Never               | ❌ Never             |
| Intermediate activations         | ✅ Yes                  | ✅ Yes (detached)    |
| Backward pass through split      | ✅ Required             | ❌ Not needed        |

The elimination of the backward pass across the split boundary reduces both communication rounds per batch (from 2 to 1) and the attack surface for gradient inversion attacks.

## 5. Limitations and Discussions

### 5.1 Sequential Relay Bottleneck

The multi-client setup uses a sequential relay: clients take turns training on their local shards before passing Layer 0 weights to the next client. This means that while Client 2 is training, Clients 1 and 3–N are idle. For N=10, wall-clock training time is approximately 10× longer than the single-client case for the same number of rounds, even if the total data seen per round is the same. A parallel aggregation strategy (analogous to FedAvg) would be more efficient but would require either sending all clients the same initial Layer 0 weights at the start of each round and averaging afterward, or designing a more sophisticated synchronization protocol.

### 5.2 Activation Privacy

While raw pixel values never leave the client, the intermediate activations sent to the server are not provably private. Model inversion attacks (Fredrikson et al., 2015) and GAN-based reconstruction methods (Zhang et al., 2020) have been shown to partially reconstruct inputs from intermediate representations, especially at shallow split points. Since our split is after the very first convolutional layer (the shallowest possible), this is a real concern. Defenses such as differential privacy noise injection (Abadi et al., 2016), dimensionality reduction at the cut layer, or deeper cut points would strengthen the privacy guarantees. The triangle activation and standardnorm preprocessing do provide some natural obfuscation, but this has not been formally quantified.

### 5.3 Single Cut Layer

The current implementation fixes the split at a single point: after Layer 0. More flexible architectures would allow the split point to be tuned as a hyperparameter, or even employ multiple cut layers (one per device in a chain). Multi-hop split learning (Thapa et al., 2022) would allow, for example, three edge devices each holding one layer of the network, with the server eliminated entirely. SCFF's layer-local loss makes this a natural extension.

### 5.4 Non-IID Convergence

As noted in Section 4.2, non-IID data distribution significantly degrades accuracy. The relay strategy does not include any mechanism to correct for distribution shift — each client updates Layer 0 on its own label distribution, and the next client may see a completely different distribution. Approaches from federated learning such as FedProx (Li et al., 2020) or SCAFFOLD (Karimireddy et al., 2020) add proximal terms or control variates to correct for this drift. Adapting these ideas to the SCFF relay — where the "global model" is the set of Layer 0 weights being relayed — is a promising direction.

### 5.5 Evaluation Protocol Limitations

The linear readout evaluation protocol, while standard in self-supervised learning, may understate the true quality of the learned representations. The frozen features are evaluated with a linear classifier only; fine-tuning or nonlinear probes might reveal richer structure. Additionally, 50 readout epochs with a fixed Adam optimizer may not be optimal across all configurations — the non-IID multi-client case in particular might benefit from a longer or differently scheduled readout.

### 5.6 Scalability Beyond CIFAR-10

The architecture (3 layers, up to 1536 channels) is specifically tuned for CIFAR-10's 32×32 images. Scaling to higher-resolution datasets (STL-10 at 96×96 or ImageNet at 224×224) would require adjustments to kernel sizes, pooling strides, and the number of layers, as well as potentially more than one split point. The `config.json` file already contains STL-10, STL-10 Parallel, and ImageNet configurations, indicating this is a known extension path.

### 5.7 Theoretical Understanding

FF-based methods, including SCFF, currently lack the theoretical convergence guarantees that exist for standard BP (e.g., via NTK theory). The conditions under which greedy layer-local contrastive training provably converges to useful representations, and how split learning topology interacts with convergence rate, remain open questions. Bridging the gap between the empirical success of SCFF and a formal theoretical framework is an important direction for future work.

### 6.2 `SCFF_CIFAR_Split.py` — Single-Client Split Learning

*(See attached file: `SCFF_CIFAR_Split.py`)*

This file implements:
- `SplitClient`: holds Layer 0, performs local SCFF training, sends detached activations
- `SplitServer`: holds Layers 1–2, trains on received activations
- `SplitTrainer`: orchestrates the full training loop and linear readout evaluation
- `run_validation_checks`: pre-training integrity validation
- Full `main` entry point with argparse CLI

Key design decisions:
- `.detach()` is called immediately after pooling in `SplitClient.train_step()`, creating a hard gradient boundary
- Epoch gating (`alleps`) allows each layer to train for a different number of epochs before freezing
- The readout concatenates features from all three layers, using `extra_pool` to reduce spatial dimensions

### 6.3 `SCFF_CIFAR_MultiClient.py` — Multi-Client Sequential Relay

*(See attached file: `SCFF_CIFAR_MultiClient.py`)*

This file implements:
- `get_client_loaders`: splits CIFAR-10 into N equal shards (IID or non-IID)
- `SplitClient`: same as above, with added `get_weights()` / `set_weights()` for weight relay
- `SplitServer`: same as above
- `MultiClientTrainer`: the sequential relay loop — all N clients train in order per round
- Full `main` entry point supporting `--num_clients N` and `--non_iid` flags

Key design decisions:
- `copy.deepcopy` of both model and optimizer state ensures relay carries full AdamW momentum
- `set_weights` recreates the optimizer bound to the new net's parameters before loading state, avoiding stale parameter references
- One round over all N clients ≈ one epoch over the full 50,000-sample training set

### 6.4 `SCFF_CIFAR_Parallel.py` — Baseline (Non-Split)

*(See attached file: `SCFF_CIFAR_Parallel (1).py`)*

This file implements the original SCFF training where all layers reside on a single device. It serves as the accuracy baseline against which the split variants are compared. The train function loops over all layers in a single `for i in range(NL)` loop with `.detach()` between layers — exactly equivalent to the split version, just without the physical device boundary.
